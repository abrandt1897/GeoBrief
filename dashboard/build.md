# Dashboard build & update run

Live dashboard: <https://claude.ai/artifact/Jsjx16BKtU824X523PA8gp> (one stable link, republished every run)

## Build

```text
python3 dashboard/build.py          # consistency checks, then writes dashboard/dist/index.html
python3 dashboard/build.py --check  # checks only
```

`build.py` exits non-zero when a check fails. Fix the data, never the check. `dashboard/dist/` is not committed. `artifact.html` is the page published to the claude.ai artifact; `index.html` is the standalone document GitHub Pages serves at <https://abrandt1897.github.io/GeoBrief/> (deployed by `.github/workflows/pages.yml` after CI passes on `main`).

## Scheduled run (6 a.m. and 6 p.m. ET, daily)

Fetching rule: use WebFetch first for any page; if it fails or returns the wrong content, retry with Firecrawl (scrape for a known URL, search for discovery). For GitHub, use plain `git` for pull/commit/push; use the GitHub connector only for Actions/CI status.

1. `git pull`. Read `state/current.md`, `state/brief.json`, the last ~10 lines of `log/events.md`, and armed rows in `data/tripwires.csv`.
2. Search news since the last event in `log/events.md`. Apply the signal rules in `skill/SKILL.md` (Trump threats weak; Iranian threats strong; supply claims contested until Kpler/Windward/PortWatch confirm).
3. **Gas (6 a.m. run only, or 6 p.m. if the day has no row):** WebFetch `https://gasprices.aaa.com/` and `https://gasprices.aaa.com/?state=NY`; check that the NY page really shows New York. If WebFetch fails, errors, or returns the wrong state, fall back to Firecrawl scrape (maxAge 0, query prompt). Record regular and diesel for each (`nat_regular`, `nat_diesel`, `ny_*`, `nyc_*`); the gas chart's Diesel view needs `nat_diesel` on every row. Append one row per date to `data/gas.csv`; never two rows for one date.
4. Append exactly one event to `log/events.md` per run (`- YYYY-MM-DD | (am, run) summary (source)`, or `(pm, run)`), even when there is more than one story: it is the run's single dashboard dispatch, and build.py rejects a second one for the same run. Open it with a bold headline of about 6–10 words right after the run tag (`(am, run) **Houthis set fire to Aramco office in Dhahran** …`); the dashboard shows the headline and opens the prose on tap, grouped by day under Morning and Evening. Then write a short prose summary: two to four full sentences that say what happened and why it matters, not a telegraphic list of fragments joined by semicolons or arrows. Skip the routine status sentence: say "no tripwire fired", "odds unchanged" or the AAA price only when one of them moved or the reason it didn't move is the news (the charts already show them; build.py rejects the stock phrases). End with the sources in parentheses. Append market readings to `data/markets.csv` when found, and a row to `data/energy.csv` for each new trading day (Brent daily close from Trading Economics <https://tradingeconomics.com/commodity/brent-crude-oil>, which the dashboard matches; EIA Brent spot when FRED has it; JKM front month (`jkm_front`) from the Investing.com historical-data page <https://www.investing.com/commodities/lng-japan-korea-marker-platts-futures-historical-data> (JKMc1; WebFetch is usually blocked there, so go straight to Firecrawl scrape); `brent_nov3` and `jkm_nov3` = the settlement of the contract that is front month on Nov. 3 (Brent JAN 27, JKM DEC 26) from CME's settlement pages <https://www.cmegroup.com/markets/energy/crude-oil/brent-crude-oil.settlements.html> and <https://www.cmegroup.com/markets/energy/natural-gas/lng-japan-korea-marker-platts-swap.settlements.html> (CME Brent Last Day settles match ICE Brent; ICE's own pages show only last price and % change, so use them only as a fallback: prior settlement = last ÷ (1 + change/100)). Both sources keep about five sessions, so fill every trading day missing since the last complete row, not just today; the Firecrawl `cmegroup-com` futures_settlements tool (product 424 Brent, 7049 JKM, with `trade_date`) returns any of those days. A row with Brent but no JKM or Nov. 3 settlements is incomplete: fill it on the next run rather than leaving it blank).

   **Physical supply (every run):** search for new Kpler, Vortexa or IEA readings on Hormuz flows, Gulf/Middle East exports and East-West/Yanbu throughput since the last date in `data/supply.csv` (weekly Kpler figures usually surface via Reuters, CNBC, Bloomberg or WSJ; the IEA Oil Market Report lands mid-month). Append one row per reading (`date,series,mbd,kind,source,note`; date = end of the averaging window; series `hormuz_kpler`, `gulf_kpler`, `hormuz_iea`, `gulf_iea` or `eastwest`; kind `7d`, `daily`, `monthly` or `estimate`, or `unconfirmed` for a single-source claim, which is kept but not plotted). Keep the file in date order, one row per date and series (keep the latest vintage and note the revision). When a reading changes the picture, add a dated level-2 (`##`) section to `log/physical-supply.md`; its last section is the note shown under the chart. East-West (`eastwest`) is pipeline throughput, which no tracker publishes directly, so search for it by name every run ("East-West pipeline", "Petroline", "Yanbu loadings", "Red Sea crude exports"): an on-the-record Saudi energy ministry or Aramco rate is `estimate` (plotted) unless a tracker contradicts it; Kpler/Vortexa/LSEG/TankerTrackers Yanbu or Red Sea crude loadings become an `estimate` of loadings + 1.0 (west-coast refinery feed, from Kpler's Sept split of 5.5 total vs ~4.5 exported), with the loadings figure in the note; an anonymous or cumulative figure stays `unconfirmed`; a confirmed halt is `0`, `daily`. If nothing new was published, leave both files alone.

5. Check each armed tripwire. If fired: set `status=fired`, `fired_on`, `evidence`. A tripwire with a set time window (a deadline, a "within N days" threat, a monthly figure that must land by a date) gets `status=expired` and a line of `evidence` saying what happened, on the first run after its window closes without firing. **On Nov. 3:** every armed tripwire whose `targets` or `effect` point at a Nov. 3 number (`nov3:*`, `gas_*`, `brent_*`, `lng_*`) moves to the year-end horizon: rewrite its effect and targets against the `ye2026` odds and year-end forecasts, or expire it if it has no year-end meaning. The dashboard moves fired tripwires to the collapsed past section 7 days after `fired_on`, with the expired ones; nothing in the CSV changes for that.
6. **Odds point (every run):** `data/odds.csv` gets a full row set per horizon dated today (the four scenarios `limited_war`, `escalated_war`, `mou_deal`, `comprehensive_deal`, defined in `state/current.md`; if today already has rows, replace them), even when nothing moved: copy the latest values with note `unchanged`, so the odds charts plot a point every day. `build.py` fails when a day with a run dispatch has no odds rows. If anything is material: re-derive odds and write them as today's rows instead; append re-forecasts to `data/forecasts.csv` (new row, same `id`, new `made_on`; never edit a past `p`; a same-day revision replaces that day's row), with `made_on` = the date (UTC) of the commit that adds the row, since a forecast counts from when it was recorded, not when it was thought of; including the eight `scen_<horizon>_<scenario>` rows, which must equal the new odds; every Nov 3 price line (`gas_*`, `brent_*`, `lng_*`) is scenario odds × the weighted bands in `data/scenarios.csv` (`build.py` computes the expected value in its error message); tripwire `targets` are moves from today's value (`key+=n` / `key-=n`), or a level (`key=v`) only for a resolution, and effects quote them as `{key}` placeholders the build fills, so they need no rebasing; check each still makes sense and run `python3 dashboard/build.py --tripwire-lines` to refresh the Live Tripwires list in `state/current.md` and `skill/SKILL.md` (a test checks it); when a tripwire fires, replace its placeholders with the numbers as of that day, since a fired effect is a record; if odds move because a scenario or forecast definition changed rather than because of news, add a row to `data/rescores.csv` (`date,horizon,note`, horizon `nov3`, `ye2026` or `all`) so the chart marks it; update `state/current.md`, `state/brief.json` (headline, status (when attacks don't move the odds, say why: unclaimed or unconfirmed hits fire no tripwire; a US strike fires `tw_us_strike` and a confirmed, named Iranian claim fires `tw_irgc_claim`), bets (year-end framed: two or three armed tripwires whose effects move the year-end odds, never a Nov 3 line; no change log on the page), blink10, deal_p, updated; Blink #10 comes from the year-end odds: no blink ≥ comprehensive, unresolved ~0) and `data/tripwires.csv`.
7. Resolve forecasts whose `resolves_on` has passed (`outcome`, `resolved_on`).
8. `python3 dashboard/build.py`. Fix any failed check before continuing. Run `python3 -m pytest tests/test_data.py` (data schema and integrity) and fix the data until it passes. Then `npm ci` (first time) and `npx prettier --write state log` so CI's format check stays green.
9. Before committing, run the rest of CI locally and fix anything it flags: `ruff check . && ruff format --check . && python3 -m mypy`, `npm run lint`, `python3 -m pytest`, and `npm run test:e2e` (in a cloud session, `CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:e2e`). Commit `run: YYYY-MM-DD am|pm — <one-line summary>` and push to `main`. If nothing changed, skip the commit.
   **CI gate (every run):** the run doesn't end until CI is green. After pushing (or, if nothing was committed, on the current `main` head), use the GitHub connector to watch every check run and workflow run on that commit (CI's `lint` and `test` jobs) until all have completed, waiting about a minute between checks. If any fails, read its job log, fix the cause (data first; never skip, disable or weaken a check or test), rerun the local checks, commit `run: YYYY-MM-DD am|pm — fix CI: <what>`, push, and watch the new commit the same way. Repeat until every check passes. If the connector can't read CI, say so in the final message instead of claiming CI passed.
10. Republish: Artifact tool, `url` = the dashboard link above, `file_path` = `dashboard/dist/artifact.html` (read the artifact first if this session hasn't). Always republish so "Updated" stays current, even when only gas moved.
11. Push notification only if a tripwire fired or any Nov 3 scenario moved ≥3 points.
